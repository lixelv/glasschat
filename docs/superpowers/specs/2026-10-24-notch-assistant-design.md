# GlassChat — голосовой ассистент в ноче и инструмент visualize

Дата: 2026-10-24. Статус: дизайн одобрен в чате, спецификация на ревью.

## Цель

Добавить в GlassChat голосового ИИ-ассистента, который всегда живёт на месте ноча MacBook
(как Dynamic Island у iPhone). Клик по ночу раскрывает его, ассистент слушает фразу, сам
определяет её конец по тишине, распознаёт речь и отвечает как агент с инструментами — коротким
текстом, с инфографикой и, по желанию, голосом.

Успех:
- после запуска приложения ноч на встроенном экране заменён формой GlassChat; она остаётся,
  пока приложение не завершено полностью (⌘Q), даже если главное окно закрыто;
- клик → говоришь фразу → после ~1,5 с тишины ответ появляется в раскрытом ноче без других действий;
- после ответа ассистент 15 с слушает продолжение, затем засыпает до следующего клика;
- модель может озвучить текст (`say`), задать пользователю вопросы с вариантами (`ask_user`)
  и (фаза 2) показать HTML-визуализацию (`visualize`) — в ноче и в обычном чате.

## Фазы

- **Фаза 1:** панель в ноче, аватар и визуализация звука, голосовой цикл (запись, детекция
  тишины, распознавание, дослушивание), чат ассистента с лимитом контекста, озвучка
  (`app_say` + кнопка «Озвучить»), вопросы пользователю (`app_ask_user`), вкладка настроек.
  **После фазы 1 — стоп:** пользователь проверяет и даёт правки.
- **Фаза 2:** инструмент `app_visualize` — рендер в ленте чата и в ноче.

## Вне рамок

- Глобальная горячая клавиша вызова.
- Отправка записанного аудио напрямую в мультимодальную чат-модель (`input_audio`): только
  распознавание Apple или звуковая модель.
- Перебивание ассистента голосом во время озвучки (barge-in).
- Автоматические тесты (в проекте их нет; проверка — запуском приложения).
- Песочница и ограничения для HTML из `visualize`.

## 1. Панель в ноче

### Окно
- `NotchPanel` — подкласс `NSPanel`: `styleMask` = `.borderless` + `.nonactivatingPanel`,
  прозрачный фон, без тени, `level` выше меню-бара (`.mainMenu + 3`),
  `collectionBehavior` = `.canJoinAllSpaces`, `.stationary`, `.fullScreenAuxiliary`,
  `.ignoresCycle`. `canBecomeKey` = `true` (нужен ввод текста в карточке вопросов),
  `canBecomeMain` = `false`. Панель не активирует приложение и не забирает фокус у текущего
  приложения при наведении и клике по форме; ключевой она становится только когда пользователь
  кликает в текстовое поле.
- Размер панели фиксирован = максимальный размер раскрытой формы; верхний край — верх экрана,
  по горизонтали — по центру ноча. Прозрачная часть пропускает клики: глобальный и локальный
  монитор `mouseMoved` переключает `ignoresMouseEvents` в зависимости от того, находится ли
  курсор внутри текущей формы (прямоугольника формы с небольшим запасом). Глобальный монитор
  событий мыши не требует прав Accessibility.
- Клик вне формы и Esc сворачивают раскрытый ноч (глобальный монитор `leftMouseDown`
  + локальный для Esc, когда панель ключевая).

### Геометрия (`NotchGeometry`)
- Экран: встроенный дисплей, если у него есть ноч (`safeAreaInsets.top > 0`), иначе
  `NSScreen.main`.
- Размер ноча: ширина = `screen.frame.width − auxiliaryTopLeftArea.width − auxiliaryTopRightArea.width`,
  высота = `safeAreaInsets.top`. Без ноча — «пилюля» 180×32 pt по центру сверху
  (высота = высота меню-бара, если она известна).
- Пересчёт при `NSApplication.didChangeScreenParametersNotification` (подключение/отключение
  мониторов, смена разрешения) — панель переезжает.

### Состояния формы (`NotchView`)
Форма — чёрная `NotchShape` (прямой верх, скругление снизу, маленькие вогнутые «ушки» сверху,
как у аппаратного ноча), размер анимируется пружиной (`.spring(response: 0.4, dampingFraction: 0.8)`).

| Состояние | Размер | Содержимое |
|---|---|---|
| **Закрыт** | ровно ноч | пусто; сливается с аппаратным ночем |
| **Закрыт, ассистент занят** | ноч + 28 pt по бокам | слева мини-аватар (думает/говорит), справа мини-полоски |
| **Закрыт, ответ готов (не прочитан)** | ноч + 28 pt | аватар, мягкая пульсация точки справа |
| **Наведение** | ноч + 36 pt по бокам, +4 pt вниз | мини-аватар и полоски |
| **Раскрыт** | ширина 480 pt, высота по содержимому, максимум 520 pt | см. ниже |

Раскрытый ноч:
- **Верхняя строка** (высотой с ноч): слева от физического ноча — аватар (28 pt), справа —
  визуализация звука. Середина строки пустая (её закрывает физический ноч).
- **Тело** (скролл, если не помещается):
  - распознанная фраза пользователя — мелким вторичным цветом (в режиме Apple обновляется
    во время речи);
  - шаги инструментов текущего ответа — компактные чипы (иконка + имя инструмента + статус);
  - ответ — Markdown через существующий `MarkdownMessage` в компактном размере шрифта;
  - карточка вопросов `ask_user`, если она ожидает ответа;
  - строка ошибки, если есть.
- **Нижняя строка кнопок** (иконки): 🔊 «Озвучить» последний ответ, ⏹ «Стоп» (останавливает
  запись/ответ/озвучку), ↗ «Открыть в окне» (показывает чат ассистента в главном окне,
  создавая окно при необходимости), ＋ «Новый разговор».
- Клик по аватару в раскрытом ноче — начать слушать (если сейчас не слушает и не отвечает).

Поведение:
- Клик по закрытому ночу → раскрытие и сразу запись.
- Сворачивание (клик вне / Esc) останавливает запись и озвучку; идущий ответ дописывается
  в фоне (состояние «закрыт, занят»), по завершении — «ответ готов». Повторное раскрытие
  показывает последний ответ; если ответ уже закончен — снова начинает слушать, если ещё
  идёт — просто показывает его.

### Жизненный цикл приложения
- Если ассистент включён в настройках, `applicationShouldTerminateAfterLastWindowClosed`
  возвращает `false`: закрытие главного окна не завершает приложение, иконка в Dock остаётся,
  клик по ней открывает окно. Если выключен — поведение как сейчас (`true`).
- Панель создаётся в `applicationDidFinishLaunching` и при включении настройки; убирается при
  выключении.

## 2. Аватар и визуализация звука

### `AssistantAvatar`
Белый мягкий сквиркл с двумя чёрными овальными глазами, рисуется `TimelineView(.animation)` +
`Canvas`. Принимает `mood` и `level: Double` (0…1).

| mood | Анимация |
|---|---|
| `idle` | медленное «дыхание» (масштаб ±3 %), моргание каждые 3–6 с |
| `listening` | подпрыгивание и растяжение по `level` голоса, глаза чуть шире |
| `thinking` | глаза смотрят вверх-вбок, вокруг по орбите бегут 3 точки |
| `speaking` | внизу появляется «рот», открывается по `level` озвучки |
| `error` | глаза-дуги вниз, лёгкое покачивание |

### `Waveform`
5–7 белых скруглённых полосок справа.
- слушает: высоты по истории уровня микрофона (последние N замеров);
- распознаёт/думает: бегущая волна (синус по фазе);
- говорит: по уровню озвучки;
- покой: точки минимальной высоты.

## 3. Голосовой цикл

### Машина состояний (`AssistantController`, `@Observable @MainActor`)
```
idle ──клик──▶ listening ──конец фразы──▶ transcribing ──текст──▶ answering
  ▲                │ (нет речи в окне ожидания)                      │
  └────────────────┘                                                 ▼
  ▲                                                    (если app_say) speaking
  │                                                                  │
  └──── нет речи 15 с ◀── followUp (listening, окно 15 с) ◀───────────┘
```
- `listening` после клика: если речь не началась за «Ожидание речи» (8 с по умолчанию, меняется
  в расширенных настройках, §6) — тихо в `idle` (ноч остаётся раскрытым).
- `followUp`: то же, что `listening`, но окно ожидания начала речи = настройка «Дослушивание»
  (15 с по умолчанию). Если речь началась — обычная запись и новый цикл; если нет — `idle`,
  дальше только по клику.
- Пустой результат распознавания → обратно в `listening` того же окна (не отправляем).
- «Стоп» в любом состоянии → `idle` (отмена записи, `ChatController.stop`, остановка озвучки).
- Исключение для `answering`: пока в ноче открыта карточка `app_ask_user`, запись и
  распознавание работают как в `listening`, но распознанная фраза уходит в карточку (§4),
  а не новым сообщением.

### Запись и детекция тишины (`VoiceRecorder`)
- `AVAudioEngine`, tap на `inputNode`, буфер 1024 кадра; запись в WAV (16 кГц, моно, 16 бит)
  во временный файл, параллельно буферы отдаются распознавателю Apple (для живого текста).
- Уровень: RMS буфера → дБ; публикуется `level` (0…1) для аватара и полосок, ~30 раз/с.
- Фон шума: экспоненциальное скользящее среднее уровня, пока речь не идёт; первые 300 мс
  после старта — калибровка.
- Начало речи: уровень > фон + 12 дБ дольше 150 мс.
- Конец фразы: после начала речи уровень < фон + 6 дБ непрерывно дольше настройки
  «Пауза тишины» (1,5 с по умолчанию).
- Ограничение: фраза максимум 60 с — затем принудительный конец.
- Во время озвучки (`speaking`) микрофон не слушает.

### Распознавание (`Transcriber`)
Протокол с двумя реализациями; выбор — по настройке «Звуковая модель»:
- **Пусто (по умолчанию) → `AppleTranscriber`:** `SpeechAnalyzer` + `SpeechTranscriber`
  (macOS 26, на устройстве), локаль — из настройки «Язык» (по умолчанию системная). Живые
  (volatile) результаты показываются в ноче во время речи, финальный текст — после конца
  фразы. Если локаль не поддерживается `SpeechTranscriber` — fallback на `DictationTranscriber`
  (тот же `SpeechAnalyzer`, больше языков; проверено: `SpeechTranscriber` в macOS 26.5 не знает
  `ru_RU`, а `DictationTranscriber` знает). Не поддерживает ни один — ошибка с советом задать
  звуковую модель. Языковой пакет не установлен — загрузка через `AssetInventory` с прогрессом
  в ноче.
- **Задана модель (например `whisper-1`) → `APITranscriber`:** `POST {base}/audio/transcriptions`
  (multipart: `file` = WAV, `model`, опционально `language`) тем же base URL и токеном, что чат.
  Ответ — `{"text": ...}`.

### Чат ассистента
- `AppSettings.assistantChatID: UUID?` — постоянный чат ассистента. Если его нет или он удалён —
  создаётся новый с заголовком «Assistant» и моделью по умолчанию; он виден в сайдбаре как обычный.
- «Новый разговор» создаёт новый чат «Assistant» и делает его текущим чатом ассистента;
  старый остаётся в истории.
- `ChatController` становится общим (`ChatController.shared`) для окна и ноча — состояние и так
  разложено по id чата; так кнопка Stop в окне видит ответ, начатый из ноча, и наоборот.
- Отправка: обычный `ChatController.send(text, in: assistantChatID)`. Когда id чата равен
  `assistantChatID`, контроллер сам (в том числе при Retry/Edit из главного окна) применяет:
  - «Лимит сообщений» (16 по умолчанию; 0 = без лимита). Модели
    отправляются только последние N сохранённых сообщений чата (текущее сообщение пользователя
    входит в N); если срез начинается с ответа ассистента, он сдвигается до ближайшего сообщения
    пользователя. **История в чате не удаляется.** Обычные чаты — без лимита.
  - «Промпт ассистента» из настроек — отдельным system-сообщением
    после общего системного промпта. Пустое поле = текст по умолчанию (так обновление текста
    по умолчанию в фазе 2 доходит до пользователя). Текст по умолчанию (английский, модель отвечает на языке
    пользователя): ассистент живёт в ноче MacBook, пользователь говорит голосом, фразы
    распознаны автоматически и могут содержать ошибки; отвечать очень коротко и по делу, на
    языке пользователя; числа, сравнения и структуры показывать через `glasschat__app_visualize`
    (фаза 2), говорить вслух через `glasschat__app_say` — когда пользователь просит или когда
    уместна короткая голосовая реплика; уточнять через `glasschat__app_ask_user`, а не вопросом
    в тексте, когда есть понятные варианты. Фраза про `visualize` появляется в промпте
    по умолчанию только в фазе 2, вместе с инструментом.
- Состояние ответа ассистент берёт из `ChatController.isStreaming` и сообщения в `ChatStore`
  (ответ стримится в ноч так же, как в окно). Ошибки — из `ChatController.errors[chatID]`.
- Инструменты выполняются автоматически, как и сейчас.

## 4. Новые встроенные инструменты

Добавляются в `AppTool` (группа `AppTool.key`, имена `glasschat__app_*`), доступны во всех
чатах, включая обычные.

### `app_say`
- Параметры: `text` (обязательный).
- Озвучивает текст через `Speaker`; инструмент возвращается после окончания озвучки
  (`"Spoken."`) или при остановке (`"Stopped by the user."`). Если идёт другая озвучка — она
  прерывается.
- Пока говорит, `AssistantController` в состоянии `speaking` (если ответ идёт в чате ассистента),
  микрофон выключен.

### `Speaker` (TTS)
- **По умолчанию:** `AVSpeechSynthesizer`, голос — из настройки (список
  `AVSpeechSynthesisVoice.speechVoices()`; пусто = голос системной локали). Уровень для аватара
  берётся из буферов `write(_:toBufferCallback:)` (RMS), воспроизведение — через `AVAudioEngine`.
- **Если задана TTS-модель** (например `tts-1`, `gpt-4o-mini-tts`): `POST {base}/audio/speech`
  (`model`, `input`, `voice` из настройки, `response_format: "mp3"`), воспроизведение через
  `AVAudioPlayer` с `isMeteringEnabled` для уровня.
- Кнопка 🔊 «Озвучить» (в ноче и в hover-кнопках сообщений ассистента в основном чате)
  озвучивает итоговый текст ответа без Markdown-разметки. Повторное нажатие во время озвучки —
  стоп.

### `app_ask_user`
- Параметры:
  ```json
  {"questions": [{
     "question": "Какой формат отчёта?",
     "header": "Формат",
     "options": [{"label": "PDF", "description": "для печати"}, {"label": "Markdown"}],
     "multi_select": false
  }]}
  ```
  `question` и `options` (1–6 вариантов) обязательны; 1–4 вопроса.
- Результат модели:
  ```json
  {"answers": [{"question": "Какой формат отчёта?", "answer": "PDF"}]}
  ```
  `answer` — строка (label варианта или свой текст), массив строк при `multi_select`, `null` —
  вопрос пропущен. При отмене — ошибка `"The user dismissed the questions."`
- Ожидание: `QuestionCenter` (`@Observable @MainActor`) хранит запрос по `Chat.ID` с
  continuation; инструмент ждёт ответа. Отмена ответа (Стоп, удаление чата) завершает
  запрос отменой.
- `QuestionCard` (одна view для ноча и чата):
  - вопросы по одному, сверху `header` и счётчик «1/3»;
  - варианты — кнопки; одиночный выбор сразу переходит к следующему вопросу, множественный —
    чекбоксы и кнопка «Далее»;
  - поле «Свой вариант» (Enter — принять и дальше);
  - «Пропустить» — `null` и дальше; «Назад» — к предыдущему вопросу;
  - после последнего — сводка ответов и кнопки «Подтвердить» / «Отменить»;
  - в ноче, пока карточка открыта, микрофон слушает: распознанная фраза становится «своим
    вариантом» текущего вопроса.
- В основном чате карточка показывается в ленте вместо `ToolCallCard` этого вызова, пока он
  ждёт; после ответа — обычный `ToolCallCard` (аргументы + результат).
- Если чат ассистента сейчас не раскрыт в ноче, а вопрос пришёл из него — ноч раскрывается
  сам.

## 5. Фаза 2 — `app_visualize`

- Параметры: `html` (обязательный — полный документ или фрагмент, с `<style>` и `<script>`),
  `height` (число pt, необязательный), `title` (необязательный, подпись).
- Результат модели: `"Shown to the user."`.
- `VisualizeView` — `NSViewRepresentable` над `WKWebView`:
  - `loadHTMLString(html, baseURL: nil)`; сеть разрешена (CDN-библиотеки вроде Chart.js);
  - фрагмент оборачивается в документ; в `<head>` подмешивается базовый CSS: прозрачный фон,
    `font: -apple-system`, `color-scheme: light dark`, `margin: 0`;
  - автовысота: user script с `ResizeObserver` на `document.documentElement` шлёт
    `scrollHeight` через `messageHandler`; высота view = это значение (ограничение 40…2000 pt),
    внутренний скролл выключен. Если `height` задан — фиксированная высота, скролл внутри
    разрешён;
  - ширина — вся ширина колонки сообщений (в ноче — ширина тела панели);
  - переходы по ссылкам и `window.open` открываются в браузере по умолчанию; сама страница
    не уходит со своего документа;
  - фон прозрачный (`underPageBackgroundColor = .clear`, `drawsBackground = false`).
- Где показывается: в `MessageRow` под шагом с этим вызовом (сам вызов остаётся свёрнутым
  `ToolCallCard`), в ноче — в теле над текстом ответа. HTML хранится в `ToolCall.arguments`,
  поэтому после перезапуска визуализация отрисовывается снова.
- Пока аргументы ещё стримятся — показывается заглушка с прогрессом; рендер — после того,
  как вызов получен целиком.

## 6. Настройки — вкладка «Ассистент»

| Настройка | По умолчанию |
|---|---|
| Ассистент в ноче (вкл/выкл) | вкл |
| Звуковая модель (пусто = распознавание Apple) | пусто |
| Язык распознавания Apple | системный |

## 7. Ошибки и права

- Info.plist: `NSMicrophoneUsageDescription`, `NSSpeechRecognitionUsageDescription`.
- Нет доступа к микрофону или распознаванию → аватар `error`, строка «Нужен доступ к микрофону»
  и кнопка, открывающая нужный раздел Системных настроек
  (`x-apple.systempreferences:com.apple.preference.security?Privacy_Microphone`).
- Нет устройства ввода / движок не стартовал → строка ошибки, `idle`.
- Ошибка API (транскрибация, чат, TTS) → строка ошибки в ноче (текст `APIError`), `idle`.
- TTS-модель недоступна → ошибка инструмента `app_say` с текстом ошибки (модель увидит её);
  кнопка «Озвучить» показывает строку ошибки.
- Известный риск: релизы и dev-сборки подписаны ad hoc, подпись меняется при пересборке —
  macOS может заново спрашивать доступ к микрофону после каждой сборки.

## 9. Проверка

Swift Testing и XCTest с Command Line Tools не собираются (нет плагина `TestingMacros`, нет
XCTest без Xcode — проверено). Поэтому чистая логика (детекция тишины, срез контекста, разбор
`ask_user`, геометрия ноча, multipart, обёртка HTML, текст для озвучки) проверяется встроенным
self-test в DEBUG-сборке: `scripts/selftest.sh` запускает бинарник с `GLASSCHAT_SELF_TEST=1`,
он прогоняет проверки, печатает итог и завершается кодом 0/1. Остальное — сборка
`scripts/bundle.sh --open` и ручные сценарии после каждой фазы.

Фаза 1:
1. Запуск: форма на месте ноча; наведение — подрастает; клики рядом с ночем проходят в
   приложение под ним (меню-бар работает).
2. Закрыть главное окно — ноч остаётся, приложение живо; клик по Dock открывает окно.
3. Клик → фраза → 1,5 с тишины → в ноче распознанный текст и ответ; в сайдбаре чат «Assistant».
4. После ответа заговорить в пределах 15 с — новый цикл без клика; молчать 15 с — `idle`.
5. Лимит: при 16 и длинном чате в запрос уходят 16 сообщений (проверка по логу запроса /
   ответу модели о раннем сообщении); при 0 — все.
6. «Скажи вслух…» → модель вызывает `app_say`, аватар «говорит», микрофон молчит.
   Кнопка 🔊 озвучивает ответ; с заданной TTS-моделью — через API.
7. `app_ask_user` с 2–3 вопросами: выбор варианта, свой вариант текстом и голосом, пропуск,
   «Назад», «Подтвердить»; в обычном чате — карточка в ленте; Стоп — отмена.
8. Звуковая модель `whisper-1` в настройках — распознавание через API.
9. Внешний монитор без ноча / отключение встроенного экрана — пилюля, переезд панели.
10. Отказ в доступе к микрофону — понятная ошибка и кнопка настроек.

Фаза 2:
1. Просьба «покажи график …» — модель вызывает `app_visualize`; в чате и ноче виден график
   (Chart.js с CDN), высота по содержимому; с `height` — фиксированная.
2. Тёмная и светлая темы выглядят родными; ссылки открываются в браузере.
3. Перезапуск приложения — визуализация в истории отрисовывается снова.
