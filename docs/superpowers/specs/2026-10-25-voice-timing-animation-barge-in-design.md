# GlassChat — тайминги голоса, мягкая анимация и прерывание голосом

Дата: 2026-10-25. Статус: дизайн одобрен в чате (прерывание — вариант A, эхоподавление), спецификация на ревью.
Ветка `feature/notch-assistant`; продолжает `2026-10-25-local-voice-and-file-tools-design.md`.

## Цель

1. Ответ быстрее приходит после последнего слова: пауза конца фразы по ориентирам отрасли, «умный» конец по тексту.
2. Анимация «думает» мягче, переходы между состояниями плавные.
3. Пока ассистент отвечает или говорит, осмысленные слова пользователя прерывают его: стрим и озвучка останавливаются, новая фраза отправляется как новое сообщение.

## Основание для таймингов

Опубликованных значений паузы конца фразы у Алисы, Google Assistant и Alexa нет. Есть: OpenAI Realtime — 500 мс тишины
и 300 мс звука до начала речи; отраслевой диапазон задержки определения конца фразы — 300–800 мс; естественные паузы
внутри фразы — 600–900 мс (источники — в чате 2026-10-25). Отсюда значения ниже.

## 1. Тайминги

- `AppSettings.silencePause` по умолчанию **0,7 с** (было 1,5). Сохранённое пользователем значение не трогается
  (сейчас оно не сохранено, значит, подхватится новое).
- «Умный» конец фразы. Пауза зависит от живого текста Apple (`heard`):
  - текст кончается на `.`, `?`, `!`, `…` (после обрезки пробелов) — **0,5 с**;
  - текст есть, но без такого знака — **0,9 с**;
  - текста ещё нет — значение из настройки (0,7 с).
  Выбор — чистая функция `PhrasePause.seconds(for heard: String, base: TimeInterval) -> TimeInterval`;
  `VoiceRecorder` получает метод `updateSilence(_ seconds: TimeInterval)`, а `SilenceDetector` — изменяемый
  `config.silence`; `AssistantController` вызывает его из `onPartial`. Значения 0,5/0,9 масштабируются, если
  пользователь сменил базу: `0.5 * base / 0.7` и `0.9 * base / 0.7`.
- Supertonic: `app_say` (короткие реплики, до 200 символов) синтезируется с `SynthesisOptions(quality: .fast)`;
  длинные тексты (кнопка Speak) — `.balanced`, как сейчас.
- Остальные значения не меняются: дослушивание 15 с, ожидание речи 8 с, наведение 0,3 с.
- Настройки: подпись к «Pause that ends a phrase» — «Shorter when your words already form a sentence.».

## 2. Мягкая анимация «думает»

- `AssistantAvatar`, mood `thinking`: без орбитальных точек. Лицо медленно «дышит» (масштаб 1 ± 0,02, период 2,4 с),
  глаза плавно смещаются по кривой Лиссажу (амплитуда 0,05·size, период ~3 с), вокруг — мягкое свечение
  (белый круг 1,5·size, непрозрачность 0,06–0,16, тот же период дыхания).
- Плавные переходы: параметры рисунка (смещение глаз, высота «рта», масштаб, свечение) интерполируются к целевым значениям
  нового настроения за ~0,4 с (экспоненциальное сглаживание в `TimelineView`, без скачков).
- `Waveform`: в режиме `wave` скорость в 2 раза ниже и амплитуда 60 % (`0.3 + 0.3·sin(t·3 + i·0.8)`); высоты полосок
  при смене режима сглаживаются тем же способом (~0,25 с).
- Проверка: высоты `Waveform` для `.wave` ограничены 60 % диапазона; сглаживание — чистая функция
  `Smoothing.step(current:target:dt:time:) -> Double` (при dt = time доходит на ~63 %, монотонно, без перелёта).

## 3. Прерывание голосом (barge-in)

### Общий аудиодвижок с эхоподавлением
- Новый `AudioEngineHub` (`@MainActor final class`, один `AVAudioEngine` на приложение): микрофон
  (`inputNode` с `setVoiceProcessingEnabled(true)`) и озвучка (`AVAudioPlayerNode` → `mainMixerNode`) идут через него,
  поэтому эхоподавление macOS (Voice Processing I/O) вычитает голос ассистента из микрофона.
- `VoiceRecorder` ставит tap на `hub.engine.inputNode`; `Speaker` (Supertonic и голос macOS через
  `AVSpeechSynthesizer.write`) проигрывает через `hub.player`. Движок запускается при первом использовании и не
  останавливается между фразами (перезапуск Voice Processing занимает сотни мс).
- Если включить Voice Processing не удалось (бросает или нет устройства) — запись без него, прерывание выключено до
  перезапуска приложения (лог `voice processing unavailable`).

### Слушатель прерывания
- Пока идёт ответ (`ChatController.isStreaming(chatID)`) или озвучка (`Speaker.isSpeaking`) в чате ассистента и ноч не
  в режиме вопроса, `AssistantController` держит «тихую» запись: обычный `Transcription.start` (живой текст Apple
  есть в обоих режимах распознавания) и `VoiceRecorder.record` с `wait = .infinity`; аватар и полоски при этом
  показывают ответ/речь, а не прослушивание.
- Осмысленные слова (`BargeIn.isMeaningful(heard:voiced:spoken:) -> Bool`, чистая функция) — все условия:
  - голоса ≥ 0,4 с (`SilenceDetector.voiced`);
  - в `heard` ≥ 2 слов, или 1 слово из ≥ 3 букв;
  - `!WhisperFilter.isNoise(heard)`;
  - не эхо: меньше половины слов `heard` (≥ 3 букв, без регистра) встречаются в тексте, который ассистент сейчас
    произносит или произнёс в этом ответе (`spoken`).
- При срабатывании: `Speaker.stop()`, `ChatController.stop(chatID)`, `ApprovalCenter.dismiss`, `QuestionCenter.dismiss`;
  та же запись продолжается до паузы (умный конец фразы) и уходит как новое сообщение тем же путём, что обычная фраза
  (в режиме Whisper — финальный текст Whisper с фильтром шума).
- После завершения ответа без прерывания тихая запись отменяется, дальше обычное дослушивание.
- Настройка «Interrupt by speaking» (Settings → Assistant → Notch Assistant), по умолчанию включена. Выключена —
  поведение как сейчас (микрофон молчит во время ответа).
- Правило «во время ответа клик/наведение не включают микрофон» остаётся: прерывание делает только слушатель выше.

### Ошибки и крайние случаи
- Наушники: эхоподавление не мешает, прерывание работает так же.
- Пользователь кашлянул/шум: не проходит `isMeaningful`, ответ продолжается.
- Ответ закончился в момент срабатывания: прерывание просто становится новой фразой.

## Вне рамок
- Семантическая модель конца фразы (как semantic VAD OpenAI) — используется только пунктуация живого текста.
- Прерывание в обычных чатах главного окна.

## Проверка
Встроенный self-test:
- `PhrasePause.seconds`: «.», «?», «!», «…» → 0,5; текст без знака → 0,9; пусто → база; масштаб при базе 1,4.
- `BargeIn.isMeaningful`: мало голоса; одно короткое слово; шумовая фраза; эхо (слова из `spoken`); настоящая реплика.
- `Smoothing.step` и потолок высот `.wave`.
Вживую: Supertonic говорит через динамики — ассистент не прерывает сам себя; фраза пользователя поверх речи прерывает
и уходит как новое сообщение; кашель не прерывает; время от конца фразы до начала голоса ассистента — по логу.
